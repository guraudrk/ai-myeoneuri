# 원가 구조를 무기로 바꾸는 법 — 며느리 차별화 전략

작성일 2026-08-14 · 선행 문서 `RESEARCH_2026-08-14_B2C_경쟁분석.md`, `PRD-B2C-1000subs.md`

---

## 0. 먼저 틀린 질문을 버린다

"AI 원가를 어떻게 줄일까"는 **틀린 질문이다.** 1,000 구독자 기준 실제 비용 구조는 이렇다.

| 항목 | 월 비용 (1,000명) | 비중 |
|---|---|---|
| **획득(CAC)** — 성장 국면에서 매달 발생 | 신규 100명 × 28,000원 = **280만원** | **약 78%** |
| **고객지원(CS)** — 노인 대상 앱의 숨은 비용 | 문의율 5% × 50건 × 15분 ≈ 12.5시간 + 전화 응대 | **약 10%** |
| AI API | 550원 × 1,000 = 55만원 | 약 9% |
| 인프라(Supabase·푸시·스토리지) | 약 15만원 | 약 3% |

**AI API는 전체 비용의 10분의 1도 안 된다.** 그런데 대부분의 팀이 여기만 최적화한다.

그러니 질문을 바꾼다.

> **어떻게 하면 "사용자가 늘수록 단위 원가가 내려가고, 획득 비용이 0에 수렴하며, 고객지원이 오히려 제품 가치가 되는" 구조를 만들 수 있는가?**

아래 6개는 그 답이다. 셋은 원가 축, 셋은 획득·지원 축이다.

## 원가 축

## 1. 계층형 의도 해석 — 며느리는 시간이 갈수록 API를 부르지 않는다

### 통찰

범용 어시스턴트는 사용자가 무슨 말을 할지 모른다. 그래서 매번 LLM을 부른다.
**며느리 사용자는 평생 서른 문장쯤 말한다.** "딸한테 전화해줘", "카톡 열어줘", "약국 찾아줘", "아들한테 전화".

지금까지 이 좁음은 며느리의 약점이었다(§경쟁분석 C-10). **원가 관점에서는 이게 가장 큰 자산이다.**

### 구조

현재: 모든 발화 → Gemini Flash 1회 호출.

바꿀 것 — 4단 폭포수. 위에서 걸리면 아래로 안 내려간다.

| 층 | 방식 | 원가 | 지연 | 담당 |
|---|---|---|---|---|
| **L0 슬롯 템플릿** | `{name}한테 전화해줘` 같은 정규식·형태소 규칙 | **0원** | ~5ms | 첫날부터 60% |
| **L1 개인 발화 캐시** | 과거에 해결된 (정규화 발화 → 의도) 로컬 저장 | **0원** | ~10ms | 2주 후 +25% |
| **L2 온디바이스 모델** | ML Kit GenAI / Gemini Nano (AICore). **입력·추론·출력이 기기를 떠나지 않고 클라우드 비용이 발생하지 않는다** | **0원** | ~200ms | +8% (지원 단말 한정) |
| **L3 클라우드** | Gemini Flash — 진짜 새로운 발화만 | 유료 | ~800ms | 나머지 |

### 핵심 트릭 — 슬롯 추상화가 공간을 붕괴시킨다

발화를 그대로 캐싱하면 이름 수만큼 항목이 늘어난다. **이름·장소·시간을 슬롯으로 빼내면** 수천 개의 발화가 수십 개의 템플릿으로 접힌다.

```
"지은이한테 전화해줘"   ┐
"영수한테 전화 좀"      ├→  {PERSON}한테 전화{VERB}   ← 템플릿 1개
"큰딸한테 전화해라"     ┘

"근처 약국 찾아줘"      ┐
"가까운 보일러 수리"    ├→  {PLACE_QUALIFIER} {BIZ} 찾{VERB}
"동네 병원 좀 찾아봐"   ┘
```

슬롯 값(이름·상호)은 이미 로컬 연락처와 Kakao 어댑터가 해결한다. **LLM이 필요한 건 "이 문장이 어떤 템플릿인가"뿐인데, 그건 한 번만 배우면 된다.**

### 정직한 기대치

일반 챗봇 시맨틱 캐시의 **실제 프로덕션 히트율은 20~45%**다(Technion 2026 벤치마크). 벤더 자료의 90%는 과장이다.
다만 며느리는 (a) 폐쇄 도메인, (b) 사용자당 발화 분포가 극도로 좁음, (c) 슬롯 추상화로 공간이 접힘 — 세 조건이 모두 유리하다.

**그러니 "90% 나온다"고 가정하지 말고, L0/L1/L2/L3 각 층의 히트율을 계측한다**(`PRD F0`의 `intent_parsed` 이벤트에 `resolved_by` 속성 추가). 층별 계측 없이는 절감이 실현되지 않는다.

### 부수 효과가 더 크다

- **응답이 800ms → 10ms.** 노인 사용자에게 즉답은 원가 절감이 아니라 **제품 품질 그 자체**다. "며느리가 빨라요"는 Bixby와 싸울 때 실제로 이기는 지점이다
- **비행기 모드에서도 대부분 동작한다.** 어르신 단말은 데이터가 끊기는 일이 잦다
- **인식 실패 시 재시도가 공짜다.** 지금은 재시도할 때마다 돈이 나간다

## 2. 익명 템플릿 사전 — 사용자가 늘수록 싸지고 빨라진다

### 통찰

L1 개인 캐시는 사용자마다 처음부터 다시 배운다. 그런데 **"딸한테 전화해줘"는 모든 사용자가 똑같이 말한다.**

### 구조

1. L3(클라우드)에서 새 템플릿이 발견되면, **슬롯 값을 제거한 템플릿 문자열만** 서버로 보낸다
   - 보내는 것: `{PERSON}한테 전화{VERB}` → `intent: call_contact`
   - 보내지 않는 것: 이름, 번호, 원문, 사용자 식별자
   - **개인정보가 구조적으로 포함될 수 없다.** 슬롯이 이미 다 빠져 있다
2. 서버는 템플릿 빈도를 집계해 **공용 사전**을 만든다
3. 신규 사용자는 앱 설치 시 상위 300개 템플릿을 내려받는다 → **첫날부터 L0/L1 히트율 85%**

### 왜 이게 해자인가

| | 며느리 | 경쟁자 |
|---|---|---|
| 사용자 100명 | 사전 150개, 히트율 65% | — |
| 사용자 1,000명 | 사전 400개, 히트율 85% | 처음부터 시작 |
| 사용자 10,000명 | 사전 700개, 히트율 93% | 따라오려면 같은 시간 필요 |

- **원가 곡선이 규모에 반비례한다.** 보통 SaaS는 규모가 커져도 단위 원가가 그대로다
- **지연도 같이 내려간다.** 후발주자는 항상 우리보다 느리다
- **복제 불가.** 데이터를 베낄 수 없고, 시간을 압축할 수 없다
- 자산 이름을 붙이자면 **"한국 노인 발화 템플릿 사전"**이다. 며느리가 망해도 이건 남는다

### 주의

- 템플릿 전송은 **옵트아웃 가능**해야 하고, 개인정보처리방침에 "슬롯 제거 후 템플릿만" 명시
- 슬롯 제거 로직에 테스트를 고정한다. 이름이 하나라도 새어 나가면 이 전략 전체가 부채가 된다
- 오탐 템플릿이 사전에 들어가면 전체 사용자가 틀린다 → **빈도 임계값 + 검토 큐**

## 3. 야간 배치 + 로컬 우선 저장

### 지금 새는 곳

- 주간 리포트 요약, 통화 후 할 일 정리 — **실시간일 이유가 전혀 없는데 실시간으로 부른다**
- 모든 이벤트를 Supabase에 원본으로 쌓는다

### 바꿀 것

1. **비실시간 작업은 새벽 배치로 묶는다.** 사용자 100명분 요약을 한 번에 처리하면 프롬프트 오버헤드가 분산되고, 배치 API 할인이 적용된다
2. **어르신 폰이 진실의 원천이다.** 원본은 로컬, 서버에는 자녀 웹이 필요로 하는 **집계 지표만** 올린다
   - 서버 저장량 감소 → Supabase 비용 감소
   - **개인정보 사고 표면이 줄어든다.** 이건 비용 절감이자 리스크 절감이다. 기관 계약에서 검증당하는 항목이기도 하다
3. TTS는 `expo-speech`(온디바이스, 무료)를 유지한다
   - 프리미엄 TTS로 갈 유혹이 있지만, **노인에게는 자연스러운 목소리보다 명료하고 느린 목소리가 낫다.** 싼 선택이 더 좋은 선택인 드문 경우다

## 획득·지원 축 (진짜 큰 돈)

## 4. 자녀의 진짜 목소리 — 원가 0원짜리 정서 기능

### 문제

시중에서 돈이 도는 건 정서다(효돌 월 2~6만원, ElliQ 월 $39.99). 그런데 정서를 AI로 만들면:
- **비싸다** — 실시간 음성 대화는 하루 5분에 월 4,800원, ARPU를 통째로 먹는다
- **효과가 의심스럽다** — 4개국 2,000명 12개월 종단 연구에서 소셜 챗봇 사용 증가는 **외로움 증가를 예측**했다
- **차별화가 안 된다** — 효돌·ElliQ·클로바·ChinguAI가 전부 이걸 한다

### 해법

**AI 목소리를 만들지 말고, 자녀의 진짜 목소리를 쓴다.**

- 자녀가 웹(§PRD F3)에서 30초 녹음: *"엄마, 오늘 비 온대요. 우산 챙기세요"*
- 며느리가 정해진 시간에 그 목소리로 재생
- 자녀는 매주 한 번 들어와 새 메시지를 녹음한다

### 왜 이게 이기는가

| | 원가 | 정서 강도 | 경쟁사 보유 |
|---|---|---|---|
| AI 합성 컴패니언 | 월 4,800원 | 중 (그리고 장기 부작용 근거 있음) | **전부 보유** |
| **자녀 실제 목소리** | **월 0원** (오디오 수십 KB) | **최상** | **없음** |

- 경쟁사가 못 하는 이유가 명확하다. **그들은 "AI가 곁에 있어준다"를 팔아야 해서, 진짜 가족을 끌어들이면 자기 상품을 부정하게 된다**
- **결제자(자녀)의 리텐션 루프를 만든다.** 지금 며느리의 가장 큰 구멍은 "돈 내는 사람이 앱을 안 쓴다"는 것이다. 주 1회 녹음은 자녀를 돌아오게 하는 가장 부드러운 이유다
- AI 컴패니언 윤리 논쟁을 **정면으로 피해간다.** 며느리는 사람을 대체하지 않고 전달한다
- 마케팅 문장이 저절로 나온다 — *"AI 목소리 말고, 딸 목소리로 알려드립니다."*

### 확장

- 손주 목소리(생일 축하), 형제 릴레이 메시지
- 어르신이 답장을 음성으로 남기면 자녀 웹에 뜬다 → **양방향 루프**. 이것도 원가 0

## 5. 어르신이 며느리를 가르친다 — 존엄 · 데이터 · 원가를 한 번에

### 통찰

시중 시니어 앱은 전부 **AI가 노인을 가르치는** 구조다. 슈워요는 사용법을 알려주고, 효돌은 인지 훈련을 시키고, 케어콜은 안부를 묻는다. **어르신은 항상 배우는 쪽, 관리받는 쪽이다.**

며느리는 반대로 간다.

> **인식에 실패하면 사과하지 않는다. 배운다.**
>
> *"제가 '지은'으로 들었는데, 맞나요?"*
> *"아니야, 진영이야"*
> *"진영 님이시군요. 다음부터 기억할게요."*

### 세 가지가 동시에 해결된다

1. **정서·존엄** — 어르신이 가르치는 쪽에 선다. 이건 노인 대상 제품에서 매우 드물고, 실제로 며느리라는 이름에 가장 맞는 관계다. 며느리는 시어머니에게 배운다
2. **데이터** — 실패→정정→성공 쌍이 곧 개인 사전이 된다(§1 L1, §PRD F5). 라벨링 비용 0원
3. **원가** — 정정이 쌓일수록 L0/L1 히트율이 오르고 클라우드 호출이 줄어든다

**틀릴수록 좋아지는 앱이다.** 지금은 틀릴 때마다 재시도 비용이 나가고 사용자가 떠난다.

### 카피

> **"AI가 어르신을 가르치는 앱은 많습니다. 어르신이 AI를 가르치는 앱은 며느리뿐입니다."**

## 6. CAC와 CS를 구조로 없앤다

전체 비용의 88%가 여기 있다(§0). 기능이 아니라 **구조**로 푼다.

### 6-1. 고객지원을 제품 가치로 바꾼다

노인 대상 앱의 CS는 전화로 온다. 1인 개발자에게 이건 치명적이다.

**바꿀 것:** 어르신이 막히면 며느리가 **자녀에게 연결한다.**

> *"제가 잘 못 알아들었어요. 지은 님께 여쭤볼까요?"* → [예] → 자녀 폰에 알림 + 무엇을 하려 했는지 요약

- CS 비용이 **0원**이 된다
- 자녀 입장에서는 비용이 아니라 **가치**다 — 부모를 도왔다는 감각, 그리고 앱이 일하고 있다는 증거
- 자녀가 앱으로 돌아오는 또 하나의 이유가 된다(§4와 같은 방향)
- CS 티켓 하나가 리텐션 이벤트 하나로 전환된다

### 6-2. 스미싱 방어는 LLM을 거의 안 쓴다

스미싱은 **소수의 반복 템플릿**이다. 가족 사칭, 기관 사칭, 택배, 부고, 청첩장, 단축 URL, 해외 발신.
정규식 + 키워드 스코어링으로 재현율 0.85는 나온다. **회색 구간(점수 애매)만** 온디바이스 모델 → 그래도 애매하면 클라우드.

→ 최대 해자 기능이 **월 API 비용 거의 0원**으로 돌아간다. 게다가 원문이 기기를 안 떠나서 개인정보 관문도 통과한다.

### 6-3. 획득: 어르신이 어르신에게 판다

CAC 28,000원을 광고로 지불하면 1,000명에 2,800만원이다. 1인 개발자에게 불가능하다.

**어르신의 통화 상대는 대부분 같은 문제를 가진 어르신이다.** 이게 다른 어떤 앱에도 없는 유통 채널이다.

| 루프 | 작동 | 비용 |
|---|---|---|
| **경로당·복지관 오프라인 전파** | 한 명이 큰 목소리로 "지은이한테 전화해줘" 하면 옆 사람이 본다. 노인 커뮤니티는 물리적으로 밀집해 있고 구전 신뢰도가 극히 높다 | 0 |
| **형제 알림 루프** | 위험 알림이 형제 3인에게 간다 → 형제도 자기 부모에게 깔고 싶어진다 | 0 |
| **자녀 목소리 초대** | 자녀가 메시지를 녹음하려면 웹에 들어와야 하고, 거기서 형제를 부른다 | 0 |
| **SilverLink 기관 역류** | 복지사가 어르신 가족에게 소개 | 0 |
| **보이스피싱 콘텐츠 SEO** | 자녀의 검색 의도가 명확하다 | 시간 |

**구체적 실행:** 경로당 20곳에 A4 한 장 — *"모르는 번호가 오면 며느리가 먼저 받습니다"* + 큰 QR.
유료 광고보다 이게 먼저다. **CAC가 검증되기 전에 광고비를 쓰지 않는다.**

## PRD 반영 사항

`PRD-B2C-1000subs.md`에 아래를 추가·수정한다.

- **F0** — `intent_parsed` 이벤트에 `resolved_by: L0|L1|L2|L3` 속성 추가. 층별 히트율을 주간 지표 5번으로 승격
- **F2-2** — 스미싱 분류를 "규칙 우선, 회색 구간만 모델"로 명시 (원가 0 목표)
- **F3** — 자녀 웹에 **음성 메시지 녹음** 화면 추가 (§4). 우선순위를 리포트보다 앞

- **신규 F8** — 계층형 의도 해석 + 익명 템플릿 사전 (§1, §2). F5와 병합해 진행
