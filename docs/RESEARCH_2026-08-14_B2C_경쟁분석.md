# AI 며느리 B2C 심층 경쟁분석 — 부족한 점과 앞서나갈 점

작성일 2026-08-14 · 기준 커밋 versionCode 47 · 목표 **B2C 구독자 1,000명 / 월 매출 500만원 이상**
결제 주체 **자녀·보호자** 가정 (오너 확정, 2026-08-14)

---

## 0. 결론 먼저

1. **지금의 며느리는 "부족한 앱"이 아니라 "과금 구조가 아예 없는 앱"이다.** 코드베이스 전체(`package.json`, `src/`, `app/`)에 결제·구독·계측 코드가 **한 줄도 없다.** 기능 갭보다 이게 먼저다.
2. **경쟁에서 지고 있는 지점은 음성 성능이 아니라 "자녀가 왜 돈을 내는가"다.** 시중 유료 시니어 서비스(효돌 월 2~6만원, ElliQ $29.99~39.99)는 전부 **정서·안심**을 판다. 며느리는 **도구 편의**를 판다. 도구 편의는 Bixby가 무료로 준다.
3. **1,000 유료 구독자는 MAU 약 1.7만 명, 설치 약 5.5만 건을 요구한다.** 이건 기능 문제가 아니라 유통 문제다. 어르신은 앱을 찾지 않으므로 **획득 채널이 자녀여야 하고, 자녀가 설치하는 이유는 보이스피싱과 안부다.**

### 1.3 제품 정체성 충돌 — 먼저 해소해야 할 것

`silverlink-web-input/CLAUDE.md`의 북극성은 **"기관 20곳 × 15만원 = 월 300만원(B2B)"**, 제1원칙은 **"어르신은 앱을 설치하지 않는다"**다.
그런데 AI 며느리는 **어르신이 설치해서 쓰는 앱**이다. 두 문서는 정면 충돌한다.

또한 ADR-012는 며느리를 "SilverLink의 어르신 단말"로 재포지셔닝했다. 이 경우 며느리는 **독립 매출을 낼 수 없는 부속품**이 된다.

> **결정 필요 (ADR-017 후보):** B2C 전환을 확정한다면 ADR-012를 명시적으로 수정하고, `silverlink-web-input/CLAUDE.md`의 제1원칙에 "AI 며느리는 예외" 조항을 넣어야 한다. 이걸 안 하면 앞으로 모든 세션에서 에이전트가 B2C 기능을 "제1원칙 위반"으로 거절한다.

## 2. 경쟁 지형 — 3개 레이어

며느리는 서로 다른 3개 시장의 경계에 서 있고, 각 레이어마다 강자가 다르다.

### 레이어 1 — 공공 AI 안부전화 (B2G, 우리 시장 아님)

| 서비스 | 규모 | 방식 |
|---|---|---|
| 네이버 클로바 케어콜 | **전국 약 150개 기관 / 약 5만 명**, 전체 지자체 절반 이상. 일본 이즈모시 수출 | AI가 어르신에게 **전화를 건다**(로보콜) |
| SKT 누구 돌봄 케어콜 | 경남 시작 → 전국 확대 | 로보콜 + 지자체 리포트 |
| KT AI 케어 | AI 스피커 기반, **개인 고객 대상 판매 안 함** | 지자체·기관 계약 전용 |
| NHN 와플랫 | 독거노인종합지원센터 협력 | AI 생활지원사·복지콜 |

**판단:** 예산이 지자체에서 나오고 조달 절차를 거친다. 1인 개발 B2C가 들어갈 곳이 아니다. `silverlink-web-input/CLAUDE.md`의 "로보콜 영역에 절대 들어가지 않는다"는 판단은 지금도 옳다.

다만 **2026년 3월 27일 돌봄통합지원법 전면 시행**으로 지자체에 통합 돌봄 체계 구축 의무가 생겼다. 이건 B2G 예산 확대를 뜻하고, 동시에 **"공공이 무료로 해주는 것"의 범위가 넓어져 B2C 지불 의사를 깎는다.** 며느리는 공공이 절대 하지 않는 영역(개인 기기 조작 대행)에 있어야 한다.

### 레이어 2 — 시니어 하드웨어·정서 케어 (B2C 유료가 실제로 도는 곳)

| 서비스 | 가격 | 팔리는 이유 |
|---|---|---|
| 효돌 (AI 돌봄인형) | 렌탈 **월 2~6만원**, 약정 후 월 22,000원 | 만질 수 있는 물건 + 정서 + 자녀 안심 |
| ElliQ (이스라엘) | 하드웨어 $249 + **월 $39.99 (연납 $29.99)** | 매일 대화 + 웰니스 + 보호자 리포트 |
| 다솜(원더풀플랫폼) | 기관 중심 | 대화형 로봇 |
| ChinguAI | 한국어 음성 AI 친구, 무응답 감지 시 복지사·가족 알림 | 정서 + 이상 감지 |

**핵심 관찰:** 이 레이어의 가격은 **월 2~6만원**이다. 며느리의 목표 ARPU 5,000원보다 4~12배 비싼데도 팔린다. 이유는 하나 — **정서와 안심을 판다.** 도구 편의를 파는 순간 가격이 Bixby(무료) 쪽으로 붕괴한다.

### 레이어 3 — 시니어 스마트폰 보조 앱 (며느리의 직접 경쟁)

| 앱 | 접근 | 며느리와의 차이 |
|---|---|---|
| **슈워요** | 음성으로 묻고, **스마트폰·키오스크·ATM 사용법을 큰 글씨로 알려준다**. 읽어주기·기록·글자 크기 | **"알려주기"만 한다. 대신 해주지 않는다.** 며느리는 실행까지 간다 → 우위 |
| **효도버튼** | 필요한 기능만 큰 버튼으로 모음 | 정적 런처. AI 없음 → 며느리 우위 |
| **Bixby (One UI 8.5, 2026-03)** | Perplexity 결합으로 자연어 이해 강화. 접근성 기능 음성 제어, 화면 읽어주기, Bixby Vision 장면 설명 | **무료 · 선탑재 · Galaxy 전 기종.** 가장 위험한 경쟁자 |

**가장 아픈 진실:** "딸한테 전화해 줘"는 Bixby가 이미 무료로 한다. 며느리의 P0 유저스토리가 **경쟁 우위가 아니다.** ADR-012에서 "해자는 음성 성능이 아니라 SilverLink 연동"이라고 판단한 것은 정확했다. 그 연동이 지금 DB 마이그레이션 미실행으로 꺼져 있다는 게 문제다.

## 3. 시장 조건 — 유리한 것과 불리한 것

### 유리

- **65세 이상 인구 비중 20.7%** — 초고령사회 공식 진입. 노인 1,000만 시대
- **독거노인 가구 비중 약 36%**, 1인 가구 824만(역대 최대)
- **60대 이상 스마트폰 사용률 96%** — 기기는 이미 손에 있다
- **그런데 고령층 디지털 정보화 수준 71.8%, 실제 활용 역량은 일반 국민의 57.2%**
  → 기기 보급과 활용 능력 사이의 이 격차가 **며느리가 존재하는 정확한 이유**다
- **카카오톡·유튜브는 쓰지만 금융·행정·예약에서 장벽이 급등** — 며느리가 노려야 할 태스크 목록이 여기 있다

### 불리

- **자녀가 결제하고 부모가 쓴다 = 사용자와 지불자의 분리.** 자녀는 효용을 직접 체감하지 못하므로 **가치 증명 산출물(리포트·알림)이 없으면 갱신 시점에 해지한다**
- 컨슈머 앱 freemium 유료 전환율 **약 2.1%**, AI 네이티브 제품도 6~8%가 "좋음" 수준
- 공공 무료 서비스(케어콜)가 "안부 확인"의 지불 의사를 이미 잠식
- Play Store 3회 연속 거절 이력 — 의료/건강 카테고리 금지 제약이 마케팅 문구를 묶는다

## 4. 시중 앱보다 부족한 점 — 12개

우선순위는 **"자녀가 돈을 내는 이유에 얼마나 직결되는가"**로 매겼다.

### 티어 A — 이게 없으면 매출이 0이다

**A-1. 보이스피싱·스미싱 방어가 없다 ← 가장 큰 공백**
- 2025년 상반기 **60대 이상이 보이스피싱 피해자의 30.6%** (2020년 16% → 2배). 전 연령 1위
- 전체 피해액 2023년 4,472억 → 2024년 8,545억 → 2025년 8월 8,856억
- 스미싱 피해자의 **94%가 50대 이상**, "엄마" "아빠" 호칭 정확도가 100%에 근접
- **자녀가 부모 폰에 앱을 깔아주는 동기 1순위가 이것이다.** 며느리에는 관련 기능이 전무하다
- 며느리는 이미 통화·연락처·문자 맥락에 접근 가능한 위치에 있다. **구조적으로 가장 잘 만들 수 있는 팀인데 안 만들었다**

**A-2. 결제·구독 인프라가 없다**
- IAP 라이브러리 미설치, 가격 정책 미정, 무료/유료 경계 미정의
- 월 500만원을 목표로 세웠는데 청구할 코드가 없다

**A-3. 자녀 쪽 진입점이 없다**
- 결제 주체가 자녀인데, 자녀는 어르신 폰의 작은 "⚙ 가족 연결 설정" 버튼으로만 등장
- 자녀 본인 기기(iOS 포함)에서 볼 화면이 필요하다. 앱을 새로 만들 필요는 없고 **웹**이면 충분하다

**A-4. 계측이 없다**
- 원격 이벤트 수집 없음 → 활성 사용자 수, 발화 성공률, 전환 퍼널을 알 수 없다
- 1,000명 목표는 측정 없이 도달 불가능하다

### 티어 B — 이게 없으면 해지된다

**B-5. 리텐션 설계가 없다**
- ADR-016으로 약 알림을 지웠다. 지금 앱을 매일 열 이유는 "전화 걸 때"뿐인데, 그건 기본 전화 앱이 더 빠르다
- 시중 유료 서비스(효돌·ElliQ·ChinguAI)는 전부 **매일 먼저 말을 건다**. 며느리는 항상 기다린다

**B-6. 자녀에게 가는 가치 증명이 없다**
- ElliQ가 월 $39.99를 받는 근거는 보호자에게 가는 웰니스 리포트다
- 며느리의 리포트 기능은 SilverLink 쪽에 있고, 브리지는 DB 미적용으로 꺼져 있다

**B-7. 대화 맥락이 없다**
- `intentParser.ts`는 **단발 요청-응답**이다. 멀티턴 없음, "누구라고요?" 되묻기 없음, 이전 대화 기억 없음
- 클로바 케어콜은 이미 **과거 대화를 활용하는 "기억하기" 기능**으로 연속 대화를 한다. 이 격차가 크다

**B-8. 정서 축이 완전히 비어 있다**
- 며느리는 100% 도구다. 그런데 이 시장에서 돈이 도는 곳은 정서다
- 단, **AI 컴패니언은 양날의 검이다.** 2,000명 이상 4개국 12개월 종단 연구는 소셜 챗봇 사용 증가가 **외로움 증가를 예측**했다고 보고했고, 21일 RCT(N=183)에서도 전반적 효과는 없었다. 사회적 로봇 개입 9건 중 6건은 유의미한 감소를 보고했다
- **따라서 "AI가 친구가 되어드립니다"로 가면 안 된다.** 뒤에서 제안하는 "사람에게 되돌리는 설계"가 정답이다

### 티어 C — 경쟁 우위에 필요

**C-9. 노인 음성 인식이 범용 엔진 그대로다**
- Android 기본 `SpeechRecognizer`를 쓴다. 노인 음성은 발화 속도 저하, 잦은 휴지, 불안정한 조음, 쉰 목소리(presbyphonia), 마비말장애로 **범용 ASR에서 체계적으로 성능이 떨어진다**는 것이 다수 논문의 일치된 결론이다
- 지금은 error 11 재시도로 증상을 덮고 있을 뿐, 정확도 자체를 올리는 장치가 없다

**C-10. 태스크 범위가 좁다**
- 전화 / 앱 실행 / 즐겨찾기 / 리마인더. 그런데 고령층의 실제 장벽은 **병원 예약, 은행, 공공서비스 신청, 열차 예매, 키오스크**에 있다
- 슈워요는 이 영역을 "설명"으로 이미 커버한다. 며느리는 "실행"으로 이겨야 하는데 아직 못 한다

**C-11. iOS 없음 / APK 69.5MB**
- 어르신 단말이 안드로이드인 건 맞지만, **자녀 단말은 iPhone일 확률이 높다.** 자녀 표면을 웹으로 만들면 해결된다
- 69.5MB는 저사양 구형 단말에서 설치 이탈 요인이다

**C-12. 원가 모델이 없다**
- Gemini Live(실시간 음성) 기준 대략 **입력 $0.005/분 + 출력 $0.018/분 ≈ $0.023/분**
- 하루 5분 대화 × 30일 = 150분/월 ≈ **$3.45 ≈ 약 4,800원**
- **ARPU 5,000원 계획에서 원가가 ARPU를 다 먹는다.** 이 계산을 하지 않고 "AI가 매일 말 걸어주는 기능"을 만들면 팔릴수록 적자다

## 5. 앞서나가기 위해 개발해야 할 것 — 기술 각도

### 5-1. ★ 보이스피싱·스미싱 온디바이스 방어 — 최우선 해자

**왜 며느리만 할 수 있나**
- 이미 통화 흐름·연락처·발화 맥락 안에 들어가 있다
- 이미 `security/promptInjection.ts`로 "적대적 입력을 데이터로만 취급"하는 사고방식과 코드가 있다
- 클로바·SKT는 로보콜이라 **수신 통화 안에 들어갈 수 없다.** 구조적으로 우리만 되는 자리

**구현 방향**
1. **모르는 번호 수신 시 인터셉트 화면** — 큰 글씨로 "저장되지 않은 번호입니다. 가족이 아닐 수 있어요"
2. **온디바이스 문자 스캐닝** — 정규식 + 소형 분류기. 청첩장/부고/택배/기관 사칭 패턴. 원문은 절대 서버로 보내지 않는다 (개인정보 관문 통과)
3. **위험 발화 실시간 경보** — "지금 계좌번호를 불러달라고 했나요? 잠깐 멈추세요"
4. **자녀 즉시 알림** — 여기가 자녀가 돈을 내는 지점이다. `safetyAlertBridge.ts`를 그대로 재사용 가능
5. **1초 검증 버튼** — "정말 딸인지 확인" → 저장된 진짜 번호로 발신

**포지셔닝 문장:** *"모르는 번호가 오면, 며느리가 먼저 받습니다."*
이건 Bixby가 하지 않고, 클로바가 할 수 없고, 효돌이 못 하고, **자녀가 즉시 이해하는 가치**다. Play Store 건강 카테고리 제약도 건드리지 않는다.

### 5-2. 노인 특화 ASR — 정확도를 제품 지표로 승격

- **개인화 어휘 바이어싱:** 사용자의 연락처 이름·관계어·거주 지역 상호를 인식 힌트로 주입. 노인 음성 ASR 논문의 화자 적응(speaker adaptation) 접근을 저비용으로 구현하는 실전 버전
- **재발화 학습 루프:** 인식 실패 → 재발화 → 성공 쌍을 로컬에 축적해 개인 사전 강화. `auditLog` 구조 재사용
- **발화 속도·휴지 허용 확장:** 노인 음성의 특징이 slower rate와 increased pauses다. 침묵 타임아웃을 기본값보다 길게, 사용자별로 적응
- **실패 시 은혜로운 폴백:** "다시 말씀해 주세요"를 3번 반복하지 않는다. 2회 실패 시 즐겨찾기 3인 큰 버튼으로 전환
- **KPI:** 발화 1회 성공률(FUSR, First-Utterance Success Rate). 이걸 대시보드 1번 지표로 놓는다

### 5-3. 실시간 음성 — 단, 원가 규율과 함께

- Gemini 3.1 Flash Live(2026-03 출시)는 **첫 오디오 청크 약 200ms**, GPT-Realtime-2(2026-05)는 300~500ms. 네이티브 멀티모달이라 중간 텍스트 변환이 없다
- **하지만 상시 대화는 ARPU를 초과한다(§4 C-12).** 규율:
  - 기본 = 온디바이스 STT + Gemini Flash 텍스트 (현재 구조, 저렴)
  - 실시간 음성 = **상위 티어 전용 + 월 사용량 상한**
  - 자주 쓰는 발화는 결과 캐싱
- **기여마진을 코드 레벨에서 지킨다.** 사용자별 월 AI 비용을 계측(§4 A-4)하고 임계 초과 시 저비용 경로로 자동 강등

### 5-4. 화면 조작 대행 — "은행 앱 어디 눌러요"를 실제로 푼다

- 2025~2026 온디바이스 GUI 에이전트 연구가 실용 단계에 왔다. `AgentCPM-GUI`(MiniCPM-V 8B, 스크린샷 입력 → 자율 실행), MobileUse, mobilerun 등이 AndroidWorld/AndroidLab 벤치마크 위에서 돌아간다
- **며느리는 여기서 절대 "자율 실행"으로 가면 안 된다.** ADR-007(LLM은 계획만, Executor가 실행)과 PRODUCT_SPEC "범용 Accessibility Agent 제외"를 지킨다
- 대신 **가이드 모드**: 화면을 읽고 **눌러야 할 곳에 큰 화살표를 겹쳐 표시**한다. 누르는 건 사용자다
  - 금융 보안 화면·OTP·비밀번호는 코드 레벨 차단 유지 (ADR-009)
  - 이게 슈워요("설명만")와 자율 에이전트("위험") 사이의 정확한 빈자리다

### 5-5. 가족 컨텍스트 메모리

- 클로바 케어콜의 "기억하기"에 대응. 단, 우리는 **가족 관계 그래프**로 차별화
- "딸 지은이는 목요일에 전화한다", "무릎이 아프다고 지난주에 말했다"
- 자녀 리포트의 재료가 되고(§B-6), 멀티턴 대화의 기반이 된다(§B-7)

### 5-6. "사람에게 되돌리는" 설계 — 윤리이자 마케팅

- AI 컴패니언 장기 사용이 외로움을 **키울 수 있다**는 증거가 쌓이고 있다(4개국 2,000명 12개월 종단 연구). 정서적 지지를 AI에 의존시키면 인간관계에서 멀어진다는 보고도 있다
- **며느리의 성공 지표를 "며느리와의 대화 시간"이 아니라 "가족과의 실제 통화 횟수"로 잡는다**
- 대화 중 자연스럽게 "딸한테 전화해 볼까요?"로 연결. 자녀 리포트에는 *"이번 주 어머니가 가족에게 4번 전화하셨어요"*
- 이건 경쟁사가 따라 하기 어렵다. **효돌·ElliQ·챗봇은 자기 사용 시간을 늘려야 돈을 버는 구조**라 이 지표를 채택할 수 없다

## 6. 수익 모델 — 1,000명 / 월 500만원 역산

### 6-1. 가격 구조 제안

| 티어 | 월 가격(VAT 포함) | 포함 | 대상 |
|---|---|---|---|
| **무료** | 0원 | 음성 전화 걸기, 앱 실행, 즐겨찾기, 큰 글씨 | 미끼. 어르신이 습관을 들이는 구간 |
| **안심** | **9,900원** | + 모르는 번호 인터셉트, 스미싱 경보, **자녀 즉시 알림**, 주간 리포트 | 주력. 자녀 결제 |
| **안심+** | **16,900원** | + 실시간 음성 대화(월 상한), 화면 가이드, 통화 후 할 일 정리, 형제 3인까지 알림 | 상위 15~20% |

**왜 5,000원이 아닌가:** 5,000원은 (a) 실시간 음성 원가($0.023/분)를 감당 못 하고, (b) 이 시장 유료 서비스 가격대(효돌 월 2~6만원, ElliQ 월 $30~40) 대비 비정상적으로 싸서 오히려 **가치 신호를 깎는다.** 자녀 결제 상품은 커피 두 잔 값이면 통과한다.

### 6-2. 순수령액 계산 (Google Play 기준)

```
표시가 9,900원 (VAT 포함)
→ 공급가 9,000원 (VAT 10% 제외)
→ 스토어 수수료 15% 차감 (구독 첫 해부터 15% 적용 가정)
→ 순수령 7,650원 / 구독자 / 월
```

| 시나리오 | 유료 구독자 | 총매출(표시가) | 순수령 |
|---|---|---|---|
| 최소 목표 | 505명 (전원 안심) | 500만원 | 386만원 |
| **순수령 500만원** | **654명** | 647만원 | **500만원** |
| **목표(1,000명)** | 1,000명 (안심 850 + 안심+ 150) | **1,095만원** | **약 846만원** |

→ **1,000 구독자를 달성하면 목표를 크게 넘긴다.** 실질 손익분기는 **약 650명**이다. 이 숫자를 중간 목표로 박는 게 낫다.

### 6-3. 단위 원가와 기여마진

| 항목 | 월/구독자 | 근거 |
|---|---|---|
| Gemini Flash 텍스트 인텐트 (약 600 요청) | 약 100원 | 단발 짧은 프롬프트 |
| 실시간 음성 (안심+ 한정, 30분 상한) | 약 950원 | $0.023/분 × 30분 |
| Supabase / 스토리지 / 푸시 | 약 300원 | |
| 온디바이스 스미싱 분류 | 0원 | 로컬 추론 |
| **가중 평균 원가** | **약 550원** | 안심 85% + 안심+ 15% 가정 |
| **기여마진** | **약 7,100원** | 안심 순수령 7,650원 기준 (보수적) |

**1,000명 기준 월 기여마진 약 710만원.** 인프라 고정비와 스토어 수수료를 빼도 목표는 성립한다. **단, 실시간 음성을 무료·무제한으로 푸는 순간 이 표는 무너진다.**

### 6-4. 획득 퍼널 — 실제 난이도

```
설치            55,000
  ↓ 30% (어르신 앱은 이탈이 크다)
MAU             16,500
  ↓ 6% (AI 네이티브 제품 "좋음" 하한)
유료 구독자      1,000
```

**LTV / CAC**
- 평균 구독 유지 12개월 가정 → LTV = 7,100 × 12 = **약 85,000원**
- LTV:CAC = 3:1 기준 → **허용 CAC 약 28,000원**
- 유료 광고로만 채우면 1,000명 × 28,000원 = **2,800만원**. 1인 개발자에게 무리다

**따라서 획득은 유료 광고가 아니라 아래여야 한다:**

| 채널 | 논리 | 비용 |
|---|---|---|
| **보이스피싱 콘텐츠 SEO/유튜브** | 자녀가 검색하는 키워드가 명확하다. "부모님 보이스피싱 예방" | 시간 |
| **명절·어버이날 시즌 캠페인** | 자녀가 부모 폰을 실제로 만지는 유일한 시점 | 낮음 |
| **가족 초대 루프** | 형제 알림 확대 → 형제가 앱 설치 → 바이럴 계수 상승 | 0 |
| **SilverLink 기관 채널 역류** | 기관 복지사가 어르신 가족에게 소개 (B2C2B). ADR-012의 자산을 여기서 쓴다 | 0 |
| 요양보호사·생활지원사 커뮤니티 | 이미 관계가 있음 | 0 |

### 6-5. 현실적 타임라인

| 시점 | 유료 구독자 | 순수령 | 마일스톤 |
|---|---|---|---|
| M+3 | 30 | 23만원 | 결제 붙음, 첫 유료 전환 확인 |
| M+6 | 150 | 115만원 | 스미싱 방어 출시, 퍼널 계측 정착 |
| M+9 | 400 | 306만원 | 자녀 웹 대시보드, 리포트 |
| **M+12** | **650** | **500만원** | **실질 손익분기 = 목표 달성** |
| M+18 | 1,000 | 846만원 | 목표 구독자 수 도달 |

**1,000명·500만원을 동시에 12개월 안에 하는 건 어렵다.** 순수령 500만원(650명)을 12개월, 1,000명을 18개월로 나눠 잡는 것이 정직한 계획이다.

## 7. 리스크

| 리스크 | 확률 | 대응 |
|---|---|---|
| **Bixby가 무료로 다 해버림** | 높음 | 정면충돌하지 않는다. 해자를 **스미싱 방어 + 자녀 연결**로 옮긴다. 삼성은 자녀 계정 연동 알림을 하지 않는다 |
| **Play Store 재거절** | 중간 | 스미싱 방어는 "생산성/보안" 프레임. **"건강" 단어 금지 규칙 유지**. 통화·문자 권한은 사용 목적 문서를 미리 준비 |
| **통화·문자 권한 정책 강화** | 높음 | Google은 `READ_CALL_LOG`/`READ_SMS`를 지속 조인다. **온디바이스 처리 + 최소 권한**으로 설계하고, 권한 없이도 동작하는 축소 모드를 반드시 만든다 |
| **자녀가 6개월 뒤 해지** | 높음 | 주간 리포트로 가치를 계속 보여준다. "이번 달 위험 문자 3건 차단"이 해지를 막는 문장 |
| **AI 원가 폭주** | 중간 | 사용자별 원가 계측 + 상한 + 자동 강등 (§5-3) |
| **개인정보 사고** | 낮음·치명 | 문자 원문 서버 전송 금지. 온디바이스 분류. 통화 녹음은 며느리에서 하지 않는다(ADR-008 유지) |
| **B2B/B2C 리소스 분열** | 높음 | 1인 개발자다. 다음 6개월은 **B2C 하나만** 한다고 문서에 못 박는다 |
