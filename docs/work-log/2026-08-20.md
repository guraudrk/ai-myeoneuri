## 세션: F0 계측 완성 — action_completed/action_cancelled/ai_cost_incurred 연결

### 요청과 목표

F0 계측 파이프라인 중 아직 코드에 연결되지 않은 이벤트 3종을 연결한다.

- `action_completed` — 액션이 실제로 성공했을 때 (전화 연결, 앱 실행, 즐겨찾기 추가)
- `action_cancelled` — 사용자가 확인 다이얼로그에서 명시적으로 취소했을 때
- `ai_cost_incurred` — Gemini API 응답에서 토큰 사용량(usageMetadata)을 캡처해 기록

`paywall_shown`(F1 의존)·`link_created`(F3 의존)는 블로킹 이유가 명확하므로 이번 세션에서 다루지 않는다.

### 구현 및 변경 내용

#### intentParser.ts — ai_cost_incurred

Gemini API는 응답 JSON에 `usageMetadata.promptTokenCount`와 `candidatesTokenCount`를 항상 반환한다. 기존 코드는 이 필드를 타입에 없는 것으로 취급해 버리고 있었다.

세 곳 변경:
- **`askGemini`**: `res.json()` 타입 캐스트에 `usageMetadata` 추가 → 텍스트 반환 직전 `ai_cost_incurred` 발화
- **`readPaperWithGemini`**: 동일 패턴
- **`parseIntentL3`**: 동일 패턴 — `res.json()` 직후 usageMetadata 확인 후 발화

AnalyticsService import를 파일 상단에 추가했다.

```typescript
// 세 함수 공통 패턴 (예시: askGemini)
const data = await res.json() as {
  candidates?: ...;
  usageMetadata?: { promptTokenCount?: number; candidatesTokenCount?: number };
};
if (data.usageMetadata) {
  AnalyticsService.track("ai_cost_incurred", {
    model: "gemini-2.5-flash",
    input_tokens: data.usageMetadata.promptTokenCount ?? 0,
    output_tokens: data.usageMetadata.candidatesTokenCount ?? 0,
  }).catch(() => {});
}
```

#### index.tsx — action_completed (5곳) + action_cancelled (1곳)

**action_completed** 삽입 위치 (모두 성공 분기, `handleReset()` 또는 `setScreen({type:"idle"})` 직전):

| 인텐트 | 함수 | 조건 |
|---|---|---|
| `open_app` | handleSearch | `result.status === "opened"` |
| `call_contact` | handleConfirmContact | `result.status === "dialer_opened"` |
| `search_business` | handleConfirmBusiness | `result.status === "dialer_opened"` |
| `emergency_family` | handleSearch | `result.status === "dialer_opened"` |
| `add_to_favorites` | handleSearch Alert onPress | 추가 버튼 눌림 |

**action_cancelled** 삽입 위치:
- `add_to_favorites` Alert "취소" 버튼 onPress — 기존에 onPress가 없던 자리에 람다로 추가

### 문제와 해결 과정

특별한 문제 없음. `geminiPost()`는 raw `Response`를 반환하므로 함수 내에서 `res.json()`을 호출하는 세 곳 각각에 변경이 필요했다(한 곳에서 공통 처리 불가).

### 기술적 의사결정

**왜 action_cancelled를 add_to_favorites 한 곳에만 추가했는가:** 다른 인텐트(call_contact, search_business)는 후보 목록 화면을 보여주다가 그냥 다른 것을 누르면 상태가 바뀐다 — Alert의 명시적 "취소" 버튼이 없다. "사용자가 기다리다 화면을 닫는 것"과 "취소 버튼을 직접 누르는 것"은 의미가 다르다. 후자만 `action_cancelled`로 기록하는 것이 더 정확한 행동 데이터다.

### 테스트 및 검증

- `npx tsc --noEmit`: 통과 (출력 없음)
- 기존 테스트 실패: `recommendation.test.ts` 등 11개 스위트가 AsyncStorage `window is not defined` / expo ESM 변환 미설정으로 실패 — 이번 변경 전부터 존재하던 문제이며 내 변경과 무관

### 변경 파일

- `src/features/intent/intentParser.ts`: AnalyticsService import 추가, askGemini/readPaperWithGemini/parseIntentL3 usageMetadata 캡처

3. 지금 뭘 해야 해요? (납부/병원/약/가족에게 보여주기/무시 등 구체적 행동)

### 기술적 의사결정

F2-3을 제거한 이유: 통화 중 음성 인식을 동시에 돌리는 것은 SpeechRecognizer 리소스 충돌이 잦고, ADR-022에서 이미 "보이스피싱 탐지" 포지셔닝을 버렸으므로 코드에서도 제거하는 것이 일관성 있다.

B-9 프롬프트에 구조를 넣은 이유: Gemini에 자유롭게 요약시키면 문서 유형에 따라 출력 형식이 달라진다. 항목 번호를 부여하면 TTS로 읽을 때도 자연스럽게 구조가 드러난다.

### 변경 파일

- `app/(tabs)/index.tsx`: F2-3 관련 코드 전체 제거
- `src/features/intent/intentParser.ts`: B-9 프롬프트 재작성, maxOutputTokens 500
