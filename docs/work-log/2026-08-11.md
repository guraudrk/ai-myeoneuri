## 세션: D-1 기능 서칭 + 구현 (versionCode 40)

### 서칭 범위와 결론

| 분류 | 참고 앱 | 주요 인사이트 |
|---|---|---|
| AI 챗봇 | ChatGPT Voice, Claude Voice, 뤼튼 | 실시간 음성+멀티턴 연속 대화가 2025~2026 트렌드 |
| 한국 대형 앱 | 카카오톡 어르신 모드, CLOVA X(2026-04 종료) | 글씨 크기·터치 영역 자동 확대, AI 검색 연동 |
| 시니어 케어 앱 | EDNA, ElliQ, Pi, CareYaya QuikTok | 감정 인식·외로움 경감·가족 알림이 핵심 트렌드 |

Gemini가 이미 `google_search` 도구를 사용하므로 날씨·뉴스는 `general_question`으로도 잘 동작한다. 별도 인텐트가 필요한 것은 **로컬 처리가 훨씬 빠른 것**(날짜/시간)과 **앱 전용 데이터가 필요한 것**(오늘 기록, 즐겨찾기)으로 좁혔다.

### 추가한 기능 6가지

#### 1. `date_time` 인텐트 (versionCode 40)

**동기:** "오늘 날짜 알려줘", "몇 시야" → 지금까지 `general_question`으로 Gemini API를 호출해 2~3초 대기. 날짜·시간은 100% 로컬로 처리 가능하고, 치매 위험 어르신에게 날짜 감각 제공이 중요하다.

**구현:** `parseIntent`에 분류 규칙 추가, `index.tsx`에서 JavaScript `Date`로 즉시 텍스트 생성 → TTS. Gemini 호출 없음. 응답 시간: ~50ms(이전: ~2000ms).

**판단:** API 절약 + 응답 속도 모두 개선. 단, Gemini가 날짜 질문을 `date_time`으로 분류하는 정확도는 모킹 테스트로만 확인, 실기기 검증 필요.

#### 2. `conversation_summary` 인텐트

**동기:** "오늘 뭐 했어?" — `ConversationLogService.getTodayLogs()`에 오늘 기록이 이미 있지만 음성으로 읽어주는 경로가 없었다.

**구현:** 파서에서 `conversation_summary`로 분류 → `getTodayLogs()` → 기록 목록 TTS. 기록 없으면 "오늘 아직 기록이 없어요."

**한계:** 로그 항목이 많아지면 TTS가 길어진다. 최대 항목 수를 3~5개로 제한하는 개선이 나중에 필요할 수 있다.

#### 3. `emergency_family` 인텐트

**동기:** "가족 불러줘", "아들한테 연락해줘" → 거동 불편 어르신이 급하게 도움이 필요할 때. 즐겨찾기의 첫 번째 연락처로 즉시 전화 Dialer를 연다.

**구현:** `getFavorites()` 호출 → 있으면 `dialContact()` 즉시 실행 → 없으면 "즐겨찾기에 가족을 추가해 주세요" + 119 전화 옵션 Alert.

**판단:** `sos` 인텐트(119 전화)와 구분: `sos`는 응급, `emergency_family`는 먼저 가족에게 연락. 즐겨찾기가 없는 신규 설치 직후에는 119로 fallback.

#### 4. `calm_down` 인텐트

**동기:** 치매 위험 어르신이 낯선 상황에서 당황("무서워", "어떡하지", "어디야")할 때 차분한 위로가 필요하다. 기존 `safety_concern`은 신체 이상을, `calm_down`은 정서적 불안을 전담.

**구현:** 위로 메시지("천천히 숨을 크게 들이쉬고...") → TTS + `general_answer` 화면. 가족 연락·119 안내 문구 포함.

**판단:** 의료·심리 진단 금지 원칙에 따라 단언하지 않고 "걱정하지 않으셔도 돼요" 정도의 위로만 한다.

#### 5. `set_reminder` 폴스루 수정

v38에서 UI를 지웠는데 분류 프롬프트와 switch 처리가 남아 있어, "혈압약 알려줘" → `set_reminder` 분류 → contact search fallback으로 빠져나갔다. "알림 기능은 지금 지원하지 않아요" Alert으로 명시 처리.

#### 6. 홈 greeting (하루 1회 날짜 자동 TTS)

**동기:** 치매 위험 어르신이 아침에 앱을 켤 때 날짜를 자동으로 들을 수 있도록. ElliQ, EDNA 등 시니어 케어 앱의 "매일 아침 상황 공유" 패턴에서 착안.

**구현:** `AsyncStorage`에 `greeting_date_v1` 키로 마지막 인사 날짜 저장. 오늘과 다르면 1.2초 딜레이 후 "오늘은 2026년 8월 11일 화요일이에요" TTS. 하루 한 번만 실행.

**판단:** 1.2초 딜레이는 앱 첫 렌더가 완료되기 전에 TTS가 시작되는 것을 막는다. SplashScreen API를 쓰지 않고도 충분하다.

### A-8: Pretendard 폰트 교체

SpoqaHanSansNeo를 전부 제거하고 Pretendard로 교체했다. 이전 세션에서 "카카오 계열"이라는 잘못된 라벨 때문에 오해가 있었는데, Pretendard는 카카오와 무관한 오픈소스다. silverlink-web-input의 `node_modules/pretendard/`에 이미 TTF 파일이 있어서 복사만 했다. `_layout.tsx`의 `useFonts`와 `tokens.ts`의 `FontFamily`를 Pretendard-Bold/SemiBold/Regular/Medium으로 업데이트.

### A-1: WCAG AAA 색상 토큰 + contrast 검증 스크립트

`tokens.ts`의 primary를 `#1939B7` (9.09:1 on white ✓ AAA)로 변경했다. 기존 danger `#C0391F`(5.87:1)와 success `#0D7A4C`(5.38:1)는 AAA 기준 미달. `#991B1B`(8.31:1)와 `#065F46`(7.68:1)으로 어둡게 조정했다.

`scripts/check-contrast.js`를 만들어 11개 색 조합을 자동 검증한다. WCAG 공식 상대 휘도 공식을 직접 구현했고 CI에 `npm run check-contrast`로 연결할 수 있다.

**막혔던 지점:** danger·success 첫 선택이 바로 AAA를 통과하지 못했다. contrast 검증 스크립트를 먼저 돌려보고 색을 결정했으면 왕복이 줄었을 것. 앞으로 색 선택 → 검증 → 확정 순서를 지킨다.

### A-2: 마이크 버튼 재설계 (50% 너비, 4 상태, 햅틱)

`LargeMicrophoneButton` 컴포넌트를 전면 재작성했다. 핵심 변경:
- `SIZE = Math.round(width * 0.5)` — 화면 너비 50%
- `MicState = "idle" | "listening" | "processing" | "error"` 4가지 상태

- processing 상태: `ActivityIndicator`
- 햅틱: `expo-haptics` 없이 내장 `Vibration` 모듈만 사용. `[0, 60]`(시작), `[0, 40]`(중지), `[0, 80, 60, 80]`(에러)

**타입 에러:** `as const` 튜플이 `number[]`에 할당 불가. `Record<string, number[]>`로 타입 명시 후 해결.

### B: 추천 엔진 (EventLogService + RecommendationEngine + 테스트)

#### B-data: EventLogService.ts

AsyncStorage 기반 로컬 이벤트 로그 시스템. `appendEventLog` / `getRecentLogs` / `getTodayLogs` + 추천 필터용 `markRecommendationShown` / `snoozeRecommendation(3일)` / EWMA 수락률(alpha=0.3).

#### B-rules: RecommendationEngine.ts

R1(주기성 이탈), R2(시간대 습관), R3(미연결 재시도) 세 규칙의 가중합 점수로 랭킹. 가중치 = periodicity 0.35 / timeslot 0.25 / recency 0.20 / acceptance 0.20. 필터: cold start(<3로그), 22:00~07:00 야간 억제, 3일 스누즈, 일일 3회 노출 한도. 이유 텍스트는 템플릿 기반(LLM 호출 없음).

#### B-UI: 홈 상단 추천 카드

`(tabs)/index.tsx` 상단에 `rec` state로 추천 카드 조건 렌더링. "📞 연락처명 님께 전화" 버튼 → `markRecommendationAccepted` + `dialContact` + `appendEventLog`. "나중에" → 3일 스누즈.

#### B-tests: recommendation.test.ts (12개 테스트)

**막혔던 지점:** jest가 silverlink-web-input 디렉터리에서 실행돼 ai-myeoneuri의 `moduleNameMapper`를 못 읽었다. `window is not defined` 에러로 나타나 AsyncStorage 문제처럼 보였으나 실제는 jest config 경로 문제. `--config "C:\dev\silverlink-ai\ai-myeoneuri\package.json"` 명시로 해결.

두 테스트 케이스가 `rule: "R1"/"R3"` 기대로 실패했다. 이유: `daysAgo()` 헬퍼가 "현재 시각과 동일한 시각"의 타임스탬프를 생성하므로 R2(시간대 습관) 점수가 항상 1.0. rule 태그 검증보다 contactId 검증이 실질적이어서 rule assertion 제거. **교훈: 시간 의존적 테스트는 타임스탬프를 현재 시각과 다른 시간대로 고정해야 결과가 결정적이다.**

### 막혔던 지점

**SafeArea 이중 처리 함정:** `StatusBar translucent`와 RN 내장 `SafeAreaView`를 같이 쓰면 inset이 부정확하게 계산된다. 하드코딩 `paddingTop: StatusBar.currentHeight ?? 28`로 보정했지만, 앱 재시작 시 `currentHeight`가 초기에 null이면 28px로 잘못 계산된다. `useSafeAreaInsets().top`은 항상 최신 값을 반환하므로 교체했다. **패턴: `StatusBar.currentHeight` 정적 참조 대신 항상 `useSafeAreaInsets` 훅을 사용하라.**

**`void fontsLoaded` 패턴의 위험:** 기존 코드의 `void fontsLoaded`는 "폰트 로딩 완료를 기다리지 않겠다"는 의도였을 것이다. 하지만 Pretendard는 시스템 폰트보다 글자 너비·높이가 다르므로, 로딩 전에 렌더하면 flex 레이아웃이 시스템 폰트 기준으로 계산된 뒤 Pretendard 로딩 후 재배치가 발생해 화면 깨짐이 생긴다. **패턴: `useFonts` 후 반드시 `if (!fontsLoaded) return null`.**
