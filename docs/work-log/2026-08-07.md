## 세션: JS → 네이티브 `launch()` 연결 (versionCode 15)

### 문제 상황

전날 세션에서:
- `InstalledAppsModule.kt`에 `launch()` 메서드 추가 완료
- JS `intentParser.ts`는 여전히 `Linking.openURL("intent:#Intent;package=xxx;end")` 사용 중

`intent:#Intent;package=xxx;end` 방식이 실패하는 이유:

```
Linking.openURL("intent:#Intent;package=com.google.android.youtube;end")
→ ActivityNotFoundException: No Activity found to handle Intent (no ACTION, no CATEGORY)
```

Android Intent URI 포맷에서 `#Intent;package=xxx;end`는 패키지 필터만 지정할 뿐 어떤 액티비티를 시작할지(ACTION_MAIN + CATEGORY_LAUNCHER)를 명시하지 않는다. Android는 시작할 액티비티를 찾지 못하고 예외를 던진다.

반면 `pm.getLaunchIntentForPackage(packageName)`는 해당 패키지의 런처 엔트리 포인트를 OS가 직접 조회해 반환한다. 이것이 Google Assistant, Samsung Bixby, GiGA Genie 등 모든 음성 어시스턴트가 사용하는 표준 방법이다.

### 변경 내용

**`src/features/intent/intentParser.ts`**

`openAppByName` 함수 내 2순위·3순위 앱 실행 경로에서 `Linking.openURL` 제거, `InstalledApps.launch()` 대체:

```typescript
// 변경 전 (2순위)
await Linking.openURL(`intent:#Intent;package=${packageName};end`);

// 변경 후 (2순위)
await InstalledApps.launch(packageName);
```

```typescript
// 변경 전 (3순위 단일 매칭)
await Linking.openURL(`intent:#Intent;package=${matches[0].packageName};end`);

// 변경 후 (3순위 단일 매칭)
await InstalledApps.launch(matches[0].packageName);
```

1순위(커스텀 URI 스킴: `vnd.youtube:`, `kakaomap://` 등)는 유지.
이유: 유튜브, 카카오맵 등은 커스텀 스킴으로 직접 특정 화면 진입이 가능하므로 그대로 활용.

**`android/app/build.gradle`**

```groovy
versionCode 14 → 15
```

### 기술적 포인트

**왜 `intent:#Intent;...;end` 방식은 작동하지 않나:**

이 URI 포맷은 `adb shell am start -a ... -n ...` 과 같은 full intent를 URI 인코딩한 것이다. `package` 필터만 있고 `ACTION_MAIN`/`CATEGORY_LAUNCHER`가 없으면 Android는 어떤 액티비티를 시작해야 할지 알 수 없다. `getLaunchIntentForPackage`는 OS가 이 정보를 자동으로 채워주기 때문에 항상 성공한다(앱이 설치되어 있다면).

**1순위 커스텀 URI 스킴은 유지하는 이유:**

유튜브의 `vnd.youtube:video_id=xxx` 나 카카오맵의 `kakaomap://search?q=xxx` 같이 딥링크로 특정 기능에 직접 진입할 수 있는 경우, 단순히 앱을 여는 것보다 사용자 경험이 낫다. 향후 "유튜브에서 XXX 검색해줘" 같은 명령어를 지원할 때 이 경로를 활용할 수 있다.
