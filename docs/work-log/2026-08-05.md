# 2026-08-05 개발일지

## 오늘의 요약

이번 세션에서는 카카오 장소 검색의 구조적 문제를 두 가지 축에서 해결하고, 업체 검색 외의 일반 질문(환율·날씨·주가 등)에 답변하는 기능을 새로 추가했다.

카카오 검색은 GPS 좌표와 `radius` 파라미터를 함께 보낼 경우 현재 위치에서 5km 이내 결과만 반환한다. "오목교역 근처 치킨집"처럼 사용자 위치와 멀리 떨어진 지역을 지목하면 결과가 0건으로 나왔던 원인이 여기 있었다. 쿼리에 지역명(역·동·구 등)이 포함된 경우 GPS 없이 키워드 관련도 기준으로 검색하고, 포함되지 않은 경우엔 GPS만 보내고 `radius`는 보내지 않는 방식으로 수정했다. 거리 뱃지가 지역명 쿼리에서도 표시되도록 GPS는 두 경우 모두 전달한다.

일반 질문 기능은 처음에 Gemini 호출 한 번으로 인텐트 분류와 답변을 동시에 처리하도록 설계했다가, Gemini가 프롬프트 예시 답변을 그대로 복사하는 문제와 학습 데이터 컷오프로 인한 날짜·주가 오류가 연달아 발생했다. 결국 호출을 두 단계로 분리(1차: JSON 분류만, 2차: 질문 원문을 제약 없이 전달)하고, 2차 호출에 Google Search 그라운딩(`tools: [{google_search: {}}]`)을 추가해 실시간 정보도 정확하게 답변하도록 완성했다.

## 세션: Kakao 검색 거리 제한 해제 + 지역명 분기

### 요청과 목표

- "오목교역 근처 치킨집 찾아줘" → 결과 0건 문제 해결
- 거리 제한 자체를 없애 달라는 추가 요청

### 구현 및 변경 내용

`KakaoBusinessSearchAdapter.ts`에서 검색 파라미터 조합을 두 케이스로 분기했다.

| 조건 | 파라미터 |
|---|---|
| 쿼리에 지역명 포함 (역/동/구/시 등) | `x`, `y` 만 전송 (sort 없음 → Kakao 관련도 기준 정렬) |
| 지역명 없음 | `x`, `y`, `sort=distance` 전송 |
| 공통 | `radius` 미전송 → 거리 제한 없음 |

GPS는 두 케이스 모두 전송하므로 `doc.distance` 필드가 채워져 거리 뱃지가 항상 표시된다.

### 문제와 해결 과정

- **원인**: Kakao API는 `x`, `y`, `radius`를 함께 받으면 radius 내 결과만 필터링한다. 오목교역은 사용자 GPS 기준 5km 밖이었으므로 0건.
- **1차 시도**: 지역명 포함 쿼리에서 GPS 자체를 보내지 않음 → 결과는 나왔으나 거리 뱃지 없음
- **최종**: GPS는 항상 보내되 radius만 제거. 지역명 쿼리는 sort도 제거해 Kakao 관련도 기준 유지.

### 변경 파일

- `src/features/business/KakaoBusinessSearchAdapter.ts`: 파라미터 분기 로직 교체

### 커밋 정보

- `e196ae3` feat: Kakao radius removed + general Q&A via Gemini
- `f994161` fix: Gemini real answers + distance for all queries + versionCode 3

## 세션: 일반 질문 Q&A 기능 (환율·날씨·주가 등)

### 요청과 목표

- 음식점 검색 외에 환율, 날씨, 잡다한 상식 질문에도 답변하는 기능 추가
- 음성 원문을 Gemini에게 그대로 전달해 답변을 받아 화면에 표시

### 구현 및 변경 내용

**최종 아키텍처 (2단계 Gemini 호출):**

```
음성 원문
  ↓
1차 Gemini 호출 (JSON 분류 프롬프트)
  → { intent: "general_question", utterance: "..." }
  ↓
2차 Gemini 호출 (질문 원문 그대로 + Google Search 그라운딩)
  → Gemini 날것 텍스트 답변
  ↓
stripMarkdown() → 화면 표시
```

**주요 변경:**
- `ParsedIntent`에 `general_question: { utterance: string }` 타입 추가
- `askGemini(question)` 함수 신설: `tools: [{google_search: {}}]` 포함
- `app/index.tsx`: `general_answer` 화면 상태 및 카드 UI 추가
- `stripMarkdown()`: `**굵게**`, `## 제목`, `[링크](url)` 등 마크다운 기호 제거

### 문제와 해결 과정

**1차 설계 실패: 단일 Gemini 호출로 분류+답변 동시 처리**
- JSON 형식 제약 안에서 답변을 요청하니 프롬프트 예시 답변(`"1달러는 약 1,350원"`)을 그대로 복사 출력
- 원인: few-shot 예시의 구체적 숫자를 Gemini가 템플릿으로 학습해 그대로 사용

**2차 설계 실패: 예시 제거 후에도 학습 데이터 오류**
- "어제 코스피 종가" 질문에 Gemini가 "6월 10일 2,701.17"을 답변 (실제는 8월 5일, 수치도 다름)
- 원인: Gemini의 학습 데이터 컷오프 — 실시간 데이터 없음

**최종 해결: 2단계 분리 + Google Search 그라운딩**
- 분류 호출(1차)은 JSON만, 답변 호출(2차)은 프롬프트 없이 질문 원문 그대로
- `tools: [{"google_search": {}}]` 추가 → Gemini가 Google 검색 후 답변

**마크다운 문제:**
- Gemini가 `**2,701.17**` 형태로 답변 → React Native `<Text>`가 기호 그대로 표시
- `stripMarkdown()` 함수로 렌더링 전에 제거

### 기술적 의사결정

**단일 호출 vs 2단계 분리:**
- 단일 호출: API 비용 절감, 레이턴시 낮음 / JSON 형식 제약이 자연어 품질을 해침
- 2단계 분리 채택: 인텐트 분류는 구조화된 JSON, 답변은 제약 없는 자유 텍스트 → 각 Gemini 호출이 본연의 역할에 집중
- 비용: 일반 질문당 Gemini 호출 2회. 현 단계(테스트)에서는 허용 가능

**Google Search 그라운딩:**
- Gemini 2.5 Flash REST API 레벨에서 `tools: [{google_search: {}}]` 한 줄로 활성화
- 실시간 데이터가 필요 없는 질문(역사·번역·계산)에도 항상 켜두는 것이 단순하며, 검색 비용은 Gemini 측에서 필요할 때만 발생
