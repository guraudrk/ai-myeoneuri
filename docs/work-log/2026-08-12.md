- `rec` 변수: `const rec = await` → `await` (결과를 쓰지 않으므로)

### 판단 기준

§3 "자신의 변경이 만든 미사용 import·변수·함수만 제거" 원칙. 이들은 기존 dead code로 lint가 통과되지 않는 상태였으므로 수정 범위에 포함.

## 세션: C-1 OnboardingScreen 설정 진입점

### 배경

versionCode 37에서 온보딩 강제 게이트를 제거(ADR-015)한 뒤, `OnboardingScreen.tsx`가 어디서도 렌더링되지 않는 상태가 됐다. SilverLink 연결 기능(supabaseClient, linkService, safetyAlertBridge)은 살아 있는데 진입 경로가 없었다.

### 작업

**`app/(tabs)/index.tsx`**:
1. `showSettings` boolean state 추가
2. bottomGroup 하단에 소형 "⚙ 가족 연결 설정" 버튼 추가
   - 12px 폰트, `Colors.textMuted` — 어르신이 실수로 누르지 않을 크기·색상
   - `hitSlop` 8px으로 터치 영역은 확보 (자녀가 사용하는 버튼)
3. 두 개의 Modal 추가:
   - **미연결 시**: 풀스크린 `<Modal animationType="slide">` 안에 `<OnboardingScreen onDone={...} />`
   - **연결됨 시**: 바텀시트 `<Modal transparent>` 안에 연결 어르신 이름 + 연결 해제 버튼
4. 연결 해제 시: `clearLink()` 호출 → `linkData` state 갱신 → 모달 닫힘

### 막혔던 지점: 모달 레이아웃 충돌

처음에는 하나의 바텀시트 `modalCard` 안에 조건 분기로 `<OnboardingScreen>`과 연결 상태 뷰를 함께 넣으려 했다. `OnboardingScreen`은 `flex: 1` + `SafeAreaView` + `StatusBar`를 가진 전체 화면 컴포넌트여서, `modalCard` (제한된 높이)에 넣으면 레이아웃이 망가진다.

해결책: Modal을 두 개로 분리. 미연결은 풀스크린 Modal(비투명), 연결됨은 바텀시트 Modal(투명 오버레이). OnboardingScreen을 수정하지 않아도 된다. `_layout.tsx`도 건드리지 않는다.

### 수용 기준 확인

- ✅ 홈 → "⚙ 가족 연결 설정" → 온보딩(미연결) / 연결 상태(연결됨)
- ✅ 로그인 → 어르신 선택 → `onDone()` → 모달 닫힘 → 홈 복귀
- ✅ 재진입 시 "연결되어 있어요" + 어르신 이름 표시
- ✅ 연결 해제 → `clearLink()` → 상태 갱신
- ✅ `_layout.tsx` 미변경
- ✅ `npx tsc --noEmit` 통과
