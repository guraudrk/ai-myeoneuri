UI/UX 디자인 명세서 & 개발 전달 문서

고령자용 음성 비서 앱 · 핵심 흐름 A(딸에게 전화) 상세 설계 · React Native/Expo 개발 전달용

프로젝트 정정본
기존 SilverLink Blue·Navy 팔레트 적용 · 권한은 사용 시점에 요청 · 첫 MVP는 ACTION_DIAL로 전화 화면만 열기 · 실제 통화 시작을 추정하지 않음 · Dialer handoff 전 뒤로가기 취소 허용 · 오프라인 시 글자 입력 대체 경로 제공.

1. 디자인 원칙

  • 고령자용 큰 글씨/큰 버튼 — 본문 20sp 이상, 핵심 문장 24~32sp, 주요 버튼 56dp 이상(권장 64dp)
  • 한 화면에 하나의 질문, 선택지 최대 3개
  • 음성과 화면 동시 사용 — 모든 핵심 문장은 TTS와 화면 텍스트가 동일
  • 언제든 취소 가능 — 앱 내부 모든 단계에서 취소 가능. Android Dialer가 열린 뒤에는 OS 기본 동작을 따른다
  • 실행 전 반드시 확인 — 대상·행동·시점을 한 문장으로 표시 후에만 실행
  • 실패 시 다음 행동 안내 — 오류는 원인이 아니라 "지금 무엇을 할 수 있는지"로 표현

2. 정보 구조 (IA)

홈을 단일 진입점으로 두고, 깊은 메뉴 없이 3단 이하로 모든 화면에 도달한다.

홈
 ├─ 마이크(음성 흐름) → 듣는 중 → 인식 확인 → 연락처 후보 → 최종 확인 → 실행 → 결과
 ├─ 글자로 입력 (음성 흐름과 동일 경로 재사용)
 ├─ 최근 요청
 ├─ 설정 → 글자 크기 · 음성 속도 · 보호자 연결 · 권한 상태 · 실행 기록 · 긴급 중지
 └─ 보호자에게 도움 요청 → (미연결 시) 보호자 연결 유도

최초 실행: 시작 화면 → 짧은 소개 → 홈. 권한은 기능을 처음 사용하는 순간에만 이유를 설명한 뒤 요청한다.
마이크: 마이크 버튼 첫 사용 시 · 연락처: 연락처 검색 직전 · 알림: 첫 알림 생성 시 · 전화: MVP ACTION_DIAL 방식이라 CALL_PHONE 권한 없음

3. 주요 사용자 흐름

Flow A — 딸에게 전화 (완성 설계 대상)

홈 → 마이크(필요 시 마이크 권한) → 듣는 중 → "딸한테 전화해 줘" → 인식 결과 확인 → 연락처 권한 안내 → 후보(최대 3) → 최종 확인 → Android Dialer 열기 → 결과(전화 화면 열림/취소/연락처 권한 거부/오류)

Flow B — 생활 서비스 업체 검색 (본 산출물에서는 화면 설계 범위 밖, 향후 확장)

홈 → 음성 → 위치 사용 설명 → 업체 결과 최대 3개 → 상세 비교 → 전화 확인 → 결과. Flow A와 동일한 확인/실행/결과 패턴을 재사용한다.

Flow C — 통화 후 할 일 정리 (본 산출물에서는 화면 설계 범위 밖, 향후 확장)

통화 종료 → "정리할까요?" → 할 일 카드 개별 확인 → 알림 시간 확인 → 저장. Task Action Card 컴포넌트를 사용한다.

※ 이번 MVP 프로토타입은 브리프가 "가장 완성도 높게" 요구한 Flow A를 전체 상태 포함해 구현했다. Flow B/C는 동일 컴포넌트·토큰 체계로 확장 가능하도록 설계했다(13절 열린 질문 참조).

5. 화면별 상세 명세

아래는 개발 전달 필수 항목(목적/진입조건/데이터/버튼/결과/오류/TTS/접근성/뒤로가기/로딩/빈 상태)을 화면별로 기술한다. 프로토타입에서 동일 화면을 직접 조작할 수 있다.

5.1 홈

진입 조건짧은 사용 안내 완료 후 기본 진입 화면, 또는 임의 화면에서 "홈으로"
표시 데이터최근 요청 최대 3개(제목, 상태), 보호자 연결 상태(버튼 라벨에 영향 없음)
버튼마이크(중앙, 원형 148dp) · 글자로 입력 · 최근 요청 카드×N · 보호자에게 도움 요청 · 설정
클릭 결과마이크 → 필요 시 권한 안내 후 듣는 중 · 글자입력 → 인식 문장 확인 화면 · 최근 요청 카드 → 최근 요청 화면 · 보호자 도움 → 연결 상태에 따라 분기 · 설정 → 설정
오류 상태없음(진입 화면)
TTS"무엇을 도와드릴까요?"
접근성 Label마이크 버튼 accessibilityLabel="말씀하시려면 누르세요", role button
Android 뒤로가기앱에서 가로채지 않음 — OS 기본 동작
로딩 상태최근 요청 목록 fetch 중 스켈레톤 카드 2개
빈 상태최근 요청 없을 시 "아직 요청한 내역이 없어요" 문구, 카드 영역 숨김

5.2 음성 듣는 중

진입 조건홈에서 마이크 탭, 또는 결과 화면에서 재시도
표시 데이터부분 인식 텍스트(streaming), 대기 시간
버튼중지할게요
클릭 결과중지 → 홈(요청 취소) · 발화 종료 감지 시 자동으로 인식 결과 확인 화면 이동
오류 상태일정 시간(예: 6초) 무음 지속 시 "다시 한 번 말씀해 주세요" 안내, 화면 유지
TTS"지금 듣고 있어요"
접근성 Label상태 영역 aria-live="polite"로 부분 인식 텍스트 갱신 알림
Android 뒤로가기홈으로(리스닝 취소와 동일 동작)
로딩 상태펄스 애니메이션(마이크 주변 원형 확산), reduce-motion 시 정적 아이콘으로 대체
빈 상태해당 없음

5.3 인식 결과 확인

진입 조건발화 종료 인식 완료
표시 데이터인식된 문장 전체 텍스트
버튼맞아요 · 다시 말할게요
클릭 결과맞아요 → 연락처 검색(연락처 후보 화면) · 다시 말할게요 → 듣는 중
오류 상태인식 실패(빈 문자열) 시 이 화면을 건너뛰고 바로 "다시 말씀해 주세요" 안내와 함께 듣는 중으로 복귀
TTS"딸한테 전화해 줘, 이렇게 들었어요"
접근성 Label인용 카드는 role="text"로 전체가 한 번에 읽힘
Android 뒤로가기듣는 중으로 이동
로딩 상태없음(즉시 표시)
빈 상태해당 없음

5.4 연락처 후보 / 찾지 못한 상태

진입 조건인식 결과 확인에서 "맞아요" 선택 직후, 연락처 검색 실행
표시 데이터이름, 관계/설명, 마스킹된 전화번호(뒤 4자리 ••••), 최대 3건
버튼후보 카드(카드 전체 탭) · 다른 이름으로 찾기 (없음 상태: 다른 이름으로 찾기 · 보호자에게 도움 요청 · 연락처 앱 열기)
클릭 결과카드 선택 → 최종 확인(선택한 대상 반영) · 다른 이름 → 듣는 중
오류 상태검색 결과 0건 → 찾지 못한 상태 화면으로 전환
TTS"딸로 저장된 이지은 님과 회사 동료 이지은 님이 있어요. 누구에게 전화할까요?" / 없음 상태: "딸이라는 연락처를 찾지 못했어요"
접근성 Label각 카드 accessibilityLabel="이지은, 딸로 저장됨, 전화번호 끝 네 자리 1 2 3 4" 순서로 읽힘
Android 뒤로가기인식 결과 확인으로 이동
로딩 상태"연락처에서 "딸"을 찾고 있어요" + 스피너, 최소 표시시간 600ms(깜빡임 방지)
빈 상태후보 0건 = "찾지 못한 상태" 화면(별도 설계됨, 5절 위 참조)

5.5 전화 화면 열기 최종 확인 가장 중요한 안전 화면

진입 조건연락처 후보에서 대상 선택 직후
표시 데이터관계+대상 이름, 행동(Android 전화 화면 열기), 시점(지금)을 한 문장으로 결합
버튼전화 화면 열게요(filled, 아이콘 포함) · 열지 않을게요(outline)
클릭 결과전화 화면 열게요 → Dialer handoff 상태 · 열지 않을게요 → 취소 결과
오류 상태없음(확인 전용 화면, 실행 오류는 다음 화면에서 처리)
TTS"딸 이지은 님의 전화 화면을 지금 열까요?"
접근성 Label두 버튼은 색상뿐 아니라 아이콘·모양(채움/테두리)·문구로 구분되어 색맹 사용자도 구분 가능
Android 뒤로가기연락처 후보로 이동(취소 아님, 다시 선택)
로딩 상태없음
빈 상태해당 없음

5.6 전화 화면 여는 중

진입 조건최종 확인에서 "전화 화면 열게요" 선택
표시 데이터대상 이름
버튼없음(실행 중 구간)
클릭 결과ACTION_DIAL Intent 실행 성공 시 전화 화면 열림 결과로 전환하고, 실행 실패 시 오류로 전환
오류 상태Dialer 실행 실패 시 즉시 오류 상태로 전환(1~2초 이상 지연 금지)
TTS"이지은 님의 전화 화면을 열고 있어요"
접근성 Labelaria-live="polite", 스피너는 aria-hidden
Android 뒤로가기Dialer handoff 전에는 최종 확인으로 돌아가 취소. Dialer가 열린 뒤에는 OS 기본 뒤로가기를 따른다
로딩 상태이 화면 자체가 로딩 상태(최대 표시 시간 3초, 초과 시 오류 상태로 강제 전환)
빈 상태해당 없음

5.7 결과 — 전화 화면 열림 / 취소 / 연락처 권한 거부 / 오류

진입 조건전화 화면 여는 중 상태에서 Dialer handoff 결과에 따라 전환
표시 데이터대상 이름, Dialer 열림 여부, 오류 유형별 문구(음성 연결 실패/중복 요청/시간 초과/알 수 없음)
버튼전화 화면 열림: 홈으로 · 취소: 다시 시도 / 홈으로 · 연락처 권한 거부: 설정으로 이동 / 글자로 입력 / 홈으로 · 오류: 다시 시도 / 홈으로
클릭 결과표 상단 참조
오류 상태(본 화면 자체가 오류 처리 화면)모든 오류 문구는 기술 용어 없이 "다음 행동"으로 종결
TTS전화 화면 열림: "이지은 님의 전화 화면을 열었어요. 통화 버튼을 눌러 주세요" / 취소: "전화 화면을 열지 않았어요" / 권한거부: "연락처 권한이 없어 대상을 찾지 못했어요" / 오류: 유형별 안내
접근성 Label상태 아이콘은 장식(aria-hidden), 문구가 유일한 정보 전달 수단(색상에 의존하지 않음)
Android 뒤로가기홈으로 이동
로딩 상태해당 없음(최종 상태)
빈 상태해당 없음

5.8 설정

진입 조건홈에서 "설정" 탭
표시 데이터현재 글자 크기/음성 속도 선택값, 보호자 연결 상태, 권한 상태(마이크/연락처/알림)와 전화 방식(ACTION_DIAL, 별도 전화 권한 없음)
버튼글자 크기(보통/크게) · 음성 속도(느리게/보통/빠르게) · 보호자 연결 · 최근 실행 기록 · 긴급 중지/접근성 기능 해제
클릭 결과글자 크기 변경 → 앱 전역 핵심 문장 크기 즉시 반영(런타임) · 보호자 연결 → 연결 상태에 따라 도움 요청/연결 유도 화면
오류 상태권한 변경은 OS 설정 앱에서만 가능함을 안내(자체 토글 없음)
TTS"설정 화면이에요"
접근성 Label글자 크기/음성 속도 그룹은 role="radiogroup", 각 옵션 role="radio"
Android 뒤로가기홈으로 이동
로딩 상태권한 상태 조회 중 각 행 스켈레톤

5.9 보호자 도움 요청 / 연결 유도

진입 조건홈/실패 화면의 "보호자에게 도움 요청", 또는 설정의 "보호자 연결"
표시 데이터보내려는 요약 문구(상황에 맞게 자동 구성), 수신 보호자 이름
버튼연결 안 됨: 가족 연락처 추가하기 / 연결됨: 보내기 · 취소할게요
클릭 결과보내기 → 전송 완료 화면(같은 화면 내 상태 전환) · 취소 → 홈
오류 상태전송 실패 시 "전달하지 못했어요. 다시 시도해 주세요" + 다시 보내기 버튼(오류 문구 재사용 패턴)
TTS"무엇을 도와달라고 할까요?" / 연결 안됨: "연결된 보호자가 없어요"

8. 접근성 결정 사항

  • 본문 20sp 이상, 핵심 문장 28sp 이상, 어떤 화면 텍스트도 18sp 미만 없음
  • 주요 버튼 56~64dp, 아이콘 단독 버튼 금지(설정 진입도 텍스트 라벨 동반)
  • 선택지는 화면당 최대 3개, 긍정/부정 문구는 행동을 구체적으로 명시("전화 화면 열게요"/"열지 않을게요")
  • 색상만으로 상태를 구분하지 않음 — 성공/오류/거부는 아이콘+문구+배지 텍스트 동반
  • 본문 대비 16.5:1, Primary 버튼 대비 5.2:1로 WCAG AA(4.5:1) 상회
  • 모든 반복 애니메이션은 prefers-reduced-motion: reduce에서 정지
  • Dialer handoff 전에는 뒤로가기로 취소 가능하고, Dialer가 열린 뒤에는 Android 기본 동작을 따름
  • 글자 크기 "크게" 토글은 핵심 문장(홈 질문, 최종 확인 문장)에 즉시 반영

9. 보이스 & 마이크로카피 원칙

12. 개발 전달 요약

  • 디자인은 비즈니스 로직/API를 새로 정의하지 않으며, 확정된 흐름(입력 → 의도 구조화 → 안전 정책 → 사용자 확인 → 결정론적 실행기 → Android 작업 → 결과 검증 → 결과 안내)을 그대로 따른다.
  • 최종 확인 화면(5.5)과 오류 문구 원칙(9절)은 실행기 연동 시 절대 생략하지 말 것 — 안전 확인 UX의 핵심.
  • 금융 관련 화면은 실행 기능을 설계하지 않는다 — 은행 앱 열기/단계별 안내까지만 범위로 한다(브리프 10절).
  • 재사용 컴포넌트는 6절 표의 이름을 그대로 코드 컴포넌트명으로 사용할 것을 권장한다(Design Token 이름도 7절 color-*/type-* 그대로).
  • Android 뒤로가기는 5절 각 화면의 "Android 뒤로가기" 행을 그대로 네비게이션 스택 규칙으로 구현한다(Dialer handoff 전까지 back으로 취소 가능, handoff 후 OS 기본 동작).

13. 열린 질문 및 가정

  • 가정: 연락처 후보는 최근 통화 빈도/최근성으로 정렬되며, 관계 라벨("딸")은 사용자가 연락처 앱에 미리 지정해 둔 값이라고 가정했다. 실제로는 별도의 가족 관계 설정 단계가 필요할 수 있으며, 첫 실행 권한 요청과 묶지 않는다.
  • 열린 질문: Flow B(업체 검색), Flow C(통화 후 할 일)의 화면은 이번 산출물에 포함하지 않았다 — 동일 토큰/컴포넌트로 확장 설계할지, 별도 스프린트로 분리할지 확인이 필요하다.
  • 열린 질문: "글자 크기 크게" 모드를 핵심 문장 몇 곳(홈 질문/최종 확인)에만 적용했다 — 앱 전역 확대가 필요한지, 시스템 폰트 크기 설정과 연동할지 결정이 필요하다.
  • 열린 질문: 보호자 도움 요청의 실제 전송 채널(SMS/푸시/앱 내 메시지)이 아직 정해지지 않아 UI는 채널 중립적으로 설계했다.
  • 열린 질문: 다크 모드는 후순위이며 현재 SilverLink의 Light/Dark 토큰 체계와 호환되도록 역할 기반 토큰을 사용한다 — 실제 다크 팔레트 산출은 범위 밖이다.
